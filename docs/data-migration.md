# Перенос данных на другое устройство

Прогоны, проекты и файлы живут в трёх местах:

| Что | Где | Размер |
|---|---|---|
| Проекты, версии, прогоны, результаты | Postgres (`pgdata`) | ~70M |
| Файлы ВОР/ПД | `blobs` | ~13M |
| Кэш страниц PDF (пересоздаётся) | `pdfcache` | ~2M |

Redis переносить не нужно — только очереди.

## Бэкап (на старом устройстве)

```bash
make backup
# -> backups/20261021T060800Z/{db.dump,blobs/,manifest.txt}
```

Скопируйте каталог `backups/<stamp>/` на новое устройство (флешка, scp,
облако). Бэкап содержит документы и результаты — не кладите его в git
(`backups/` в .gitignore).

## Восстановление (на новом устройстве)

```bash
git clone <repo> && cd smeta-checker
git checkout dev
cp .env.example .env   # заполнить секреты (минимум POSTGRES_*, AUDIT_API_TOKEN, LLM-ключи)
# положить backups/<stamp>/ рядом
make restore SRC=backups/<stamp>
```

Скрипт остановит api/workers, зальёт дамп, восстановит файлы и поднимет
стек. Прогоны откроются по тем же ссылкам `/audits/<run_id>`.

## Важно

- `.env` не переносится бэкапом: секреты и LLM-ключи заполняются руками.
- Версии должны совпадать: бэкап от `dev@64f712a`. После `git pull` с
  новыми миграциями старый дамп может не встать — сначала восстановите,
  потом обновляйте код (`migrate` донакатит схему).
